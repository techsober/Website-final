# Architecture map (on-demand)

Deeper reference than `AGENTS.md`. Read when you need the full picture of an area.

## Rendering & routing
- Static **Astro 5** (`output: 'static'`). Pages in `src/pages/**` (file-based).
  Dynamic: `blog/[slug]`, `blog/[page]`, `blog/category/[cat]`, `projects/[slug]`.
  `src/pages/rss.xml.ts` emits the feed; `404.astro` is the not-found page.
- Layouts: `BaseLayout` (head/SEO/analytics/skip-link) → `BlogPost`, `ProjectPage`.
- `Seo.astro` centralizes `<title>`, canonical, OG/Twitter, robots, and JSON-LD.

## Content model
- Collections defined in `src/content.config.ts` (Zod schemas): `blog`,
  `projects`, `products`, `pages`. Markdown lives in `src/content/<collection>/`.
- Page singletons that aren't collections: `src/data/home.json`,
  `src/data/portfolio.json`.
- Helpers in `src/lib/content.ts` (published/sorted posts, related, reading time,
  date formatting, products, featured sort).
- Config, feature flags, and author identity in `src/lib/site.ts` (`SITE`, `NAV`,
  `SOCIALS`, `FLAGS`, `AUTHOR`). Flags derive from env presence.

## TinaCMS (the sharp edge)
- `tina/config.ts` = editor schema; must stay in sync with `src/content.config.ts`.
- `tina/tina-lock.json` = generated schema snapshot TinaCloud indexes against.
  **A stale/mismatched lock breaks the live `/admin`** (schema-mismatch error).
  Regenerate + verify it on every schema change (see the `tina-schema-change`
  skill). A lingering `tinacms` process can silently overwrite the lock with a
  stale copy — kill Tina processes and verify the lock's contents.
- Known limitation: a Tina `reference` list pointing at its own collection breaks
  codegen; use a slug `string` list and resolve entries at build time instead.
- `/admin` is generated by `tinacms build` (only when `PUBLIC_TINA_CLIENT_ID` +
  `TINA_TOKEN` exist), inside `scripts/build.mjs`.

## Cloudflare Pages Functions
- `functions/api/{contact,subscribe,stripe-webhook,download}.ts` — Workers runtime;
  shared helpers in `functions/_utils.ts`; own `functions/tsconfig.json`
  (`@cloudflare/workers-types`); not part of the Astro build.
- All guard on env presence and degrade gracefully. Read secrets from the `env`
  param. The Stripe webhook verifies signatures with Web Crypto (no SDK).

## Build & deploy
- `scripts/build.mjs` = prod wrapper: conditional `tinacms build` → `astro build`
  → `pagefind`. `build:nofind` skips Tina/Pagefind for a fast gate.
- Deploy: **Cloudflare Pages**. `main` = production (TinaCloud indexes it),
  `dev` = preview test site. `astro.config.mjs` sets `site` from the `SITE` env
  (defaults to the production domain) — used for canonical + sitemap.
- Env is fully feature-flagged; see `.env.example`. Nothing breaks without keys.

## Styling
- Vanilla CSS: `src/styles/tokens.css` (design tokens — the source of truth) +
  `global.css`. No Tailwind/CSS-in-JS. Reuse tokens/components; don't restyle ad hoc.
